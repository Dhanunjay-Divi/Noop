# NOOP Agent Entry Point

For any material NOOP code, health/fitness product, Safety/SOS, mobile, server,
research, deployment, or release task:

1. Load `.agents/skills/noop-ops/SKILL.md` and only the linked references needed
   for the task.
2. Run `.agents/skills/noop-ops/scripts/context_snapshot.sh .` when resuming an
   interrupted, compacted, stale, or transferred session.
3. Read `CLAUDE.md`, `docs/ops/ACTIVE.md`, and the newest relevant operations
   round before editing.

The skill contains stable project contracts. Current implementation state,
dirty-path ownership, verification, deployment status, and next commands live
in the repository operations records. Do not treat an old chat, screenshot,
passing build, or the skill itself as proof of completion.

Preserve unrelated and concurrent worktree changes. Keep health claims,
physical-device behavior, production state, and external launch gates bounded
by recorded evidence.

## Physical-device continuation priority

After the current app-integration pull request is merged and protected `main`
is green, the next device-connected agent must prioritize the signed iPhone and
Android install/validation round:

1. Start from clean protected `main`, run the context snapshot, and read
   `docs/handoff/NOOP-BAND-PHYSICAL-VALIDATION-HANDOFF.md`.
2. Install one exact signed candidate on a clean supported iPhone and Android
   phone; exercise first-run account/onboarding before using a preconfigured
   development state.
3. Validate the existing WHOOP comparison transport first and do not remove,
   relabel, or route around it.
4. Validate the supplier band only through the quarantined exact-model adapter
   and supplier artifacts approved for that hardware/firmware pair. The
   supplier-neutral SDK and simulator builds do not prove that transport, and
   no firmware should be flashed from a guessed package, key, or procedure.
5. Run connection, battery, live data, history catch-up, background,
   notification, diagnostics, accessibility, and source-switching cases on
   both platforms. Record failures and missing supplier inputs instead of
   weakening a gate.
6. Attach privacy-safe evidence to a new operations round and update the
   release checklist. Never claim BLE, retention, haptics, battery, sensor
   accuracy, or background behavior from a simulator.

Both GitHub repositories remain public by current owner decision. Public source
must still exclude supplier binaries, firmware, credentials, signing material,
private reference inputs, and personal or health data.
