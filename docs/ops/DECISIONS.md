# Durable NOOP Decisions

These decisions span multiple work rounds. A later round may replace one only
by documenting the reason, migration, evidence, and compatibility impact.

| ID | Decision | Status | Evidence / authority |
|---|---|---|---|
| D-001 | NOOP is local-first and account-free by default. Network features are explicit opt-ins to a destination the user chooses. | Active | `README.md`, `docs/PRIVACY_SECURITY.md` |
| D-002 | Measured, device-derived, imported/vendor, and NOOP-derived values retain distinct provenance. Missing input is not zero and an estimate is not a measurement. | Active | `docs/COMPETITIVE_CAPABILITY_AUDIT.md`, `docs/DATA_MODEL.md` |
| D-003 | Charge, Effort, Rest, autonomic load, readiness, Fitness Age, Vitality, and Wellness Age are independent transparent wellness estimates, not recovered proprietary formulas or clinical outputs. | Active | `docs/ANALYTICS.md`, `docs/FEATURE_PARITY.md`, `DISCLAIMER.md` |
| D-004 | Background collection and upload are described as best effort. Foreground catch-up, restoration, freshness, and completeness are implemented without promising an OS-controlled cadence. | Active | `docs/IOS.md`, `docs/ANDROID.md`, `docs/FEATURE_PARITY.md` |
| D-005 | App upgrades preserve the existing local container. Install in place with the same bundle identity; an uninstall or destructive reset requires explicit authorization and a verified backup. | Active | `docs/IOS.md`, round records |
| D-006 | Automatic activity and stress interruptions fail conservatively. Weak evidence stays in-app; interruptive alerts require opt-in and corroborating inputs. | Active | `docs/DETECTION_VALIDATION_PLAN.md`, `docs/releases/v9.2.0.md` |
| D-007 | BLE, overnight history, sleep, background, haptic, battery, and detector claims require representative physical-device evidence. Simulator/build success is not a substitute. | Active | `docs/CONTRIBUTING.md`, `docs/FEATURE_PARITY.md` |
| D-008 | The dependency inventory check and source-rights distribution decision are separate gates. | Superseded by D-026 | `Tools/release-legal-gate.py`, `docs/provenance/rights-status.json` |
| D-009 | A metric detail starts with the selected/latest day and then shows personal comparison, history, related signals, provenance, confidence, and education. | Active | `docs/releases/v9.2.0.md`, Today/Metric Explorer implementation |
| D-010 | A temporary App Store preview gate stores no plaintext shared code in Git or app storage. Release archives fail closed without an ignored one-way verifier; App Review receives the code only through private Review Information. The gate is a preview deterrent, not biometric encryption or strong authentication. | Active | `Strand/App/LaunchAccess.swift`, `StrandiOS/App/LaunchAccessGateView.swift`, `docs/APP_STORE_RELEASE.md` |
| D-011 | Repository-hosting metadata and source-rights evidence are separate concerns. | Superseded by D-026 | `docs/REPOSITORY_INDEPENDENCE.md`, `docs/provenance/rights-status.json`, `Tools/release-legal-gate.py` |
| D-012 | Today shows the complete metric catalog. A user's saved three-to-five Key Metrics are priority pins that lead the grid, not a visibility filter; named Recovery gauges use colors bounded to their displayed state. | Active | `Strand/Liquid/LiquidTodayView.swift`, `android/app/src/main/java/com/noop/ui/TodayScreen.kt`, `docs/ops/rounds/2026-08-23-today-metrics-recovery.md` |
| D-013 | Experimental Rhythm is an explicit-consent, descriptive view that never pages or alerts. It keeps duplicate R-R sources separate and fails closed without still resting context, including non-dismissed recorded-workout overlap. | Active | `Packages/StrandAnalytics/Sources/StrandAnalytics/RhythmScreener.swift`, `android/app/src/main/java/com/noop/ui/RhythmNightAssembler.kt`, `docs/ops/rounds/2026-08-23-explainable-trends-profile-rhythm.md` |
| D-014 | The profile display name defaults to Noop and is local UI identity only. It is not account, Friends, Self-hosted Sync, or shareable-backup identity. | Active | `Strand/Data/Profile.swift`, `android/app/src/main/java/com/noop/ui/SettingsScreen.kt`, `docs/ops/rounds/2026-08-23-explainable-trends-profile-rhythm.md` |
| D-015 | Cycle tracking is private, explicit-consent awareness. User logs anchor cadence; uncertain history suppresses forecasts; the UI does not present fertility, contraception, safe-day, or diagnostic guidance. | Active | `CyclePhaseEngine.swift`, `CyclePhaseEngine.kt`, `docs/ops/rounds/2026-08-24-cycle-tracking-metric-reconciliation.md` |
| D-016 | Profile-dependent projections advance their completion watermark only after current-target work reaches storage. Failed reads, writes, or marker persistence remain retryable. | Active | `Strand/Data/IntelligenceEngine.swift`, `android/app/src/main/java/com/noop/ui/AgeMetricReconciliationRunner.kt`, `docs/ops/rounds/2026-08-24-cycle-tracking-metric-reconciliation.md` |
| D-017 | Persisted score-bearing history remains durable, source-bound dirty work until post-backfill scoring reaches its success boundary. Device switches, cancellation, transient failures, and process restart retain a retry path. | Active | `Strand/Collect/Backfiller.swift`, `android/app/src/main/java/com/noop/ble/BackfillAnalysisRevisionLatch.kt`, `docs/ops/rounds/2026-08-24-overnight-calibration-effort-coach.md` |
| D-018 | Daily Effort is a current-day, explicit opt-in wellness planning cue. A stale or withheld range cannot notify, and the notification is never a limit or permission to train. | Active | `DailyEffortGuidance.swift`, `DailyEffortGuidance.kt`, `StrainTargetNotifier.swift`, `StrainTargetNotifier.kt` |
| D-019 | Coach context crosses a typed evidence boundary where missing, unavailable, empty, and observed states remain distinct. Personalized food discussion requires explicit logged evidence and a user-stated goal. | Active | `CoachEvidenceEnvelope.swift`, `CoachEvidenceEnvelope.kt`, `docs/ops/rounds/2026-08-24-overnight-calibration-effort-coach.md` |
| D-020 | A shared self-hosted service uses versioned per-installation credentials for biometric routes. The operator credential remains administrative, device ownership is exclusive, and cross-installation resources are not enumerable. | Active | `server/app/tenancy.py`, `server/migrations/010_installation_tenancy.sql`, `server/PRODUCTION_OPERATIONS.md` |
| D-021 | Safety delivery wording distinguishes provider state from human receipt. Automatic medical/anomaly/fall paging remains unavailable; only an explicit manual SOS can enter the paging pipeline. | Superseded by D-023 | `docs/ops/rounds/2026-08-24-safety-reliability-shared-tenancy.md` |
| D-022 | Safety retention deletes only terminal incidents and inactive contacts, preserves a bounded idempotency tombstone, and never ages active incidents or accepted contacts. Safety credentials rotate through client-supplied retry-safe versioned tokens. | Active | `server/migrations/011_safety_data_lifecycle.sql`, `server/app/safety_repository.py`, `server/SAFETY.md` |
| D-023 | Safety incidents have three modeled origins: app SOS, repeated band SOS, and a fail-closed `validated_fall` request contract. New automatic fall incidents are hard-disabled until authenticated detector attestation and every external release gate exist; an allowlist alone can never activate transport. Wellness and biometric values never page. Acknowledgement cancels bounded future SMS/voice rounds, and responder links expose latest-only location for the selected 8 or 12 hours. | Active | `server/migrations/013_safety_escalation_contract.sql`, `server/app/main.py`, `Strand/Data/SafetyPagingService.swift`, `android/app/src/main/java/com/noop/safety/SafetyPaging.kt` |
| D-024 | Customer-rendered product text uses NOOP or neutral compatible-wearable language. Runtime logs, release notes, and exports cross a scrubbed presentation boundary; internal BLE symbols, persisted identifiers, import formats, NOOP licensing, and dependency notices remain intact for compatibility and honesty. | Active | `CustomerFacingBrand.swift`, `CustomerFacingBrand.kt`, `Tools/i18n_audit.py`, `docs/ops/rounds/2026-08-25-customer-facing-brand-boundary.md` |
| D-025 | Recovery centers Rest on a causal personal `rest_quality` baseline once usable. The fixed `0.85` center is cold-start only; the fixed `0.12` scale and global anchor remain unchanged. Private reference outcomes are validation targets only and never production scoring inputs. | Active | `RecoveryScorer.swift`, `RecoveryScorer.kt`, `docs/ops/rounds/2026-08-25-validation-calibration-import-integrity.md` |
| D-026 | The repository owner represents control of the source and contribution rights consolidated into canonical NOOP and authorizes distribution under NOOP's PolyForm Noncommercial License 1.0.0. Independent dependencies remain under their own terms. Both legal gate modes validate the owner record, project license, and exact notices. | Active | `docs/provenance/OWNER-RIGHTS-DECLARATION.md`, `docs/provenance/rights-status.json`, `Tools/release-legal-gate.py` |
