# NOOP v9.2.1

Prepared **2026-09-05**. Store publication is a separate signed release step.

## Updates users can understand

- After onboarding on a new installation, or after installing a genuinely newer app version, NOOP
  presents a focused welcome for that version. It shows only the current release instead of making
  the user scroll through the entire historical changelog.
- The welcome body scrolls independently when release notes are long. **Skip**, **OK**, swipe-to-close,
  and system back all acknowledge that version, so the same notes do not interrupt the next launch.
- **More → Updates** opens the complete newest-first history at any time. The existing Settings entry
  remains available.
- A subtle multi-domain edge glow surrounds only the first-install welcome. It is persisted as a
  one-time installation event and becomes static when reduced motion or battery saving is active.
  Existing installations are migrated without receiving a false first-install celebration.
- **More** now starts with an always-visible **NOOP+** managed-storage entry, and the expanded Data
  group contains a dedicated NOOP+ row beside Backup & Sync. The destination remains visible when
  managed cloud configuration is absent and explains that local NOOP and folder backup still work.

## Reports that support root-cause analysis

- The cross-platform app-problem report added in this release can be opened by shaking the phone or
  from Test Centre. The user can optionally explain what felt buggy and include the screen visible
  immediately before reporting.
- The generated ZIP contains bounded diagnostic evidence for app responsiveness, navigation,
  lifecycle, database size and freshness, Bluetooth and synchronization state, and recent operating
  system exit or failure information where the platform provides it.
- Health databases, raw sensor history, credentials, and API keys are excluded. The temporary screen
  snapshot is explicitly optional and discarded when the report flow closes.

## Upgrade note

- This is an in-place UI and diagnostics update. It does not change metric formulas or database
  schemas. Existing data and release-note acknowledgements are preserved.
