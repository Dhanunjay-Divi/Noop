# NOOP v9.1.1

This release makes Noop a complete local-first **and optionally self-hosted**
biometric data system. Strap collection and analysis still work without an
account or server. When you opt in, the Apple and Android apps can replicate a
documented subset of your data to infrastructure you operate.

It also adds a deliberately honest parallel-reference workflow: keep wearing
and using the official WHOOP app while importing its export, compare those
official values with Noop's independently computed Charge, Effort, and Rest,
and learn how the estimates behave for you without ever relabeling one source
as the other.

## Self-hosted data service

- **FastAPI + TimescaleDB, ready for Docker Compose.** The server includes
  versioned, checksum-verified migrations, a loopback-only default port,
  health checks, a read-only container filesystem, retention controls, backup
  and restore instructions, and a small authenticated dashboard.
- **One authenticated v1 contract.** Upload, query, export, retention, and
  deletion endpoints use a bearer token you generate. Every data-bearing
  endpoint is authenticated; there is no Noop account or third-party relay.
- **Native clients.** Apple platforms use `URLSession`; Android uses the
  existing native networking stack. Sync is off until a server URL and token
  are saved and the user enables it.
- **Safe endpoint policy.** Internet-facing endpoints require HTTPS. Plain HTTP
  is accepted only for literal private, loopback, or link-local addresses so a
  self-hoster can use a trusted LAN without opening a hostname-confusion bypass.
- **Explicit storage semantics.** Uploads are archival upserts. Remote retention
  and deletion are server operations; deleting a local item does not silently
  erase the server copy.

## Replay that survives interruption

- **Durable raw outboxes.** Raw rows remain pending until the server returns the
  exact accepted acknowledgement. A failed request never marks them uploaded.
- **Deterministic batch identities.** Retries of the same logical batch are
  idempotent, including after an app restart or a lost response.
- **Keyset cursors per namespace.** Multi-year replay records progress for raw
  strap data, Noop-computed days, official imports, Apple Health, Health
  Connect, activity files, wearable imports, workouts, sleep, and journal
  entries independently.
- **Fixed full-replay window.** Starting a full replay captures a ten-year
  window and persists it until every namespace completes. Restarting the app
  cannot shrink that job back to the normal rolling refresh.
- **Normal catch-up stays bounded.** Outside an explicit replay, derived data
  uses a rolling window so edits propagate without scanning an entire history
  every time. Android can use opt-in WorkManager catch-up; Apple catches up when
  the app is active.

## Provenance all the way down

Every uploaded source has a platform-scoped installation ID, logical source ID,
namespace, paired-device ID, privacy marker, and score provenance. Stored metric,
event, daily, sleep, workout, and journal rows also retain their sync batch and
source metadata.

The server validates source roles rather than accepting an ambiguous label:

- strap measurements are raw and marked `strap_measured`;
- imported official reference values are marked
  `user_imported_whoop_export`;
- Noop scores are marked `noop_transparent_algorithm` with an algorithm
  revision;
- Apple Health, Health Connect, activity-file, wearable, and user-entered
  journal imports each have distinct provenance.

Noop reserves the official `whoop_strain` field for imported WHOOP reference
data. Its own strain-like output remains **Effort**, even when the two are shown
on the same chart.

## Parallel WHOOP comparison and personal calibration

- Import cycle, sleep, workout, and journal CSV files from an official WHOOP
  export while Noop continues collecting independently.
- Producer-aware import routing keeps official WHOOP rows, Noop exports, and
  unknown producers separate. Unknown sources are quarantined instead of being
  guessed into the reference lane.
- Compare screens show paired-day bias, mean absolute error, RMSE, and
  correlation without overwriting either series.
- Optional personal calibration trains on an earlier chronological window and
  must improve a later untouched holdout window before it is saved. Raw Noop,
  calibrated presentation, and official values remain separately visible.
- Coach explanations are consent-gated and identify official reference values
  and Noop estimates accurately. Calibration does not claim to reproduce
  WHOOP's proprietary models and is not medical validation.

## Privacy and ownership

- Self-hosted Sync, AI Coach, and Oura cloud import remain separate opt-ins.
- API tokens are stored in Keychain-backed storage on Apple platforms and
  Android Keystore-backed encrypted preferences on Android.
- The server ships with no default production token or database password and
  refuses short API tokens.
- Exports expose row-level provenance so a user can audit what was measured,
  imported, computed, and uploaded.
- The feature-parity document now distinguishes direct measurements,
  transparent approximations, official-import-only values, and known gaps.

## Stability and compatibility

- Battery refresh and connection-state guards incorporate vetted upstream BLE
  fixes and prevent several reconnect/crash edge cases.
- R-R intervals carry a stable sequence identity, preserving multiple beats
  with the same timestamp and deterministic ordering across Apple, Android, and
  the server.
- Database migrations add the replay/outbox indexes and provenance fields
  without rewriting existing local biometric history.
- Source coverage includes Apple Health, Health Connect, WHOOP and Noop CSV,
  activity files, Xiaomi, Oura export, Fitbit, and Garmin namespaces where the
  platform supports them.

## New identity

Noop's new mark is an open, interlocking **N** drawn as cyan and teal signal
loops on deep navy. The launcher icons, watch icon, documentation, and server
dashboard now share that independent visual identity. No WHOOP logos or assets
are used.

## Distribution note

Release artifacts are community builds:

- Android release artifacts use the clearly labeled **NOOP Staging** app ID and
  the repository's public debug key so they install beside other builds. That
  identity is reproducible, not a private production-signing trust anchor.
- macOS artifacts are ad-hoc signed and not notarized.
- iOS artifacts are unsigned and must be re-signed by AltStore, SideStore,
  Sideloadly, or your own Xcode signing team.

For maximum trust and platform entitlement support, build from source and sign
with keys you control.
