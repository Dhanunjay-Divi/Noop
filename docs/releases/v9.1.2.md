# NOOP v9.1.2

This is a private, noncommercial release candidate focused on preserving user
history and making every unavailable or untrusted signal fail closed. It does
not turn experimental wellness estimates into medical claims, and it does not
claim proprietary WHOOP formula parity.

## Upgrade and backup safety

- Apple encrypted exports use a versioned PBKDF2-HMAC-SHA256 and chunked
  AES-256-GCM envelope. Authentication covers the header, chunk ordering, and
  end-of-stream boundary.
- Backup snapshots include committed SQLite WAL frames. Export and decrypt use
  same-volume atomic publication, so an interrupted replacement leaves the
  previous destination intact.
- Restore validates the container and NOOP schema, stages the replacement, and
  applies it during a controlled cold-launch swap with rollback. Wrong keys,
  tampering, truncation, corrupt SQLite, and unrelated databases leave the live
  store untouched.
- Android uses the same `NOOPBAK` v1 wire envelope and a Keystore-protected
  scheduled-backup secret; cold-launch restore follows the same stage, validate,
  swap, and rollback boundary.

## Sensor and health integrity

- Apple Health and Health Connect use durable source projections and change
  tokens so source edits and deletions reconcile instead of leaving stale local
  rows.
- Apple Health refreshes the visible read spine only after the database commit.
  Optional cycle, body-composition, and detailed write-back permissions remain
  separate from core read access.
- RMSSD is not mislabeled as Apple Health SDNN. Duplicate or over-counted R-R
  windows withhold HRV and any dependent Charge or suggestion.
- Android morning summaries are generated only after a successful sync and
  scoring commit. BLE writes distinguish safe-to-retry idempotent commands from
  commands whose delivery outcome is unknown.

## Privacy and operations

- A fresh Apple install does not construct Bluetooth scanners until an explicit
  Scan action. Persisted, user-enabled background sources retain their existing
  reconnect behavior.
- Self-hosted requests are bounded and validated, errors avoid reflecting
  secrets, retention uses cross-worker locking, and database backup/restore has
  an automated verification path.
- CI actions are pinned to immutable commits. Android release builds require
  explicit signing and API-level gates and generate a dependency inventory/SBOM.

## Release boundary

The software test matrix can validate deterministic code, migrations, restore
rollback, UI contracts, and signed-bundle identity. Physical-device acceptance
still requires the documented WHOOP 4/5/MG, Oura, Apple Watch, HealthKit,
background, battery, and long-duration matrices. ECG, AFib, blood-pressure, and
fall/emergency detection remain unavailable rather than shipping as unvalidated
safety or diagnostic features.
